# Контракт для будущего подключения CRM

Интеграция с дипломом не выполнена. Сервис не подключается к его БД, не меняет заявки и ничего не отправляет клиентам. В текущей версии база знаний единая, доступ к ней защищён одним сервисным ключом.

## Вызов из Django

На стороне Django сначала проверить права текущего сотрудника на заявку. Затем получить актуальные данные ORM-запросом и отправить минимально необходимый контекст. Не передавать API-ключ в браузер дипломного приложения.

```python
import httpx

payload = {
    "question": "Подготовь ответ клиенту: что уточнить и какие условия применимы?",
    "lead": {
        "reference": str(lead.pk),
        "message": lead.comment,
        "products": [item.product_name for item in lead.items.all()],
    },
}

async with httpx.AsyncClient(timeout=400) as client:
    response = await client.post(
        "http://support-assistant:8010/v1/drafts",
        headers={"Authorization": f"Bearer {service_key}"},
        json=payload,
    )
    response.raise_for_status()
    result = response.json()
```

Пример показывает форму запроса, а не готовый Django view. ORM и проверку прав оформить с учётом выбранного sync/async-обработчика. Вызов нельзя выполнять внутри длительной транзакции БД.

Если `status=ready` и `generation_mode=ollama`, показать черновик, вопросы и источники. При `generation_mode=extractive` это выдержки, а не сгенерированный черновик. При `status=insufficient_evidence` показать недостающие сведения. Ни один из вариантов не подтверждает истинность произвольного текста модели автоматически.

Показать источник с `title`, `version`, `page` и `text`. Сохранение или отправку ответа делать отдельным подтверждённым действием пользователя в CRM.

## Коды ошибок

| HTTP | Значение | Действие вызывающего сервиса |
|---|---|---|
| 401 | Не принят сервисный ключ | Исправить конфигурацию; не повторять автоматически |
| 409 | Несовместимый режим или лимит базы | Проверить настройки/объём данных |
| 413/415/422 | Файл или поля запроса не подходят | Исправить запрос |
| 429 | Заняты места генерации | Повторить с учётом Retry-After |
| 502 | Модель вернула некорректный JSON, ссылки или неподтверждённые числовые значения | Показать ошибку; не использовать неподтверждённый текст |
| 503/504 | Индекс/модель недоступны или истёк таймаут | Ограниченный повтор с паузой |

Ответы об ошибке содержат `error.code`, `error.message` и `request_id`. Этот же идентификатор передаётся в `X-Request-ID`. Он используется для поиска в логах; текст заявки и ключ не журналируются приложением.

## Что понадобится при развитии

- При нескольких независимых командах/организациях добавить серверную изоляцию баз знаний и проверку доступа до поиска. Один ключ текущей версии даёт доступ ко всей базе и операциям с документами.
- Для актуальных цен, статусов, остатков и аналитических показателей использовать проверяемые API CRM. Сохранённые документы не являются источником актуальности этих значений.
- Агентные вызовы инструментов и запись в CRM — отдельный следующий этап. В текущем сервисе LLM только составляет текст.
- При нескольких экземплярах API потребуется заменить локальные ограничения конкурентности и SQLite на общие механизмы. Сейчас запускается один worker.
