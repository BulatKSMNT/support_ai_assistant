# Проверка первой версии

Дата: 7 октября 2026 года. Проверки выполнены локально, в том числе на реально запущенных контейнерах. Это не результат внешнего CI или промышленной эксплуатации.

## Среда

- Python тестового клиента: 3.12.13; Python API в контейнере: 3.12.15.
- Ollama: 0.32.14; Qdrant Server: 1.19.2; qdrant-client: 1.19.1.
- Генерация: `qwen2.5:1.5b`, эмбеддинги: `embeddinggemma`.
- Запуск моделей на CPU, параметр Ollama `num_thread=4`; максимум одна загруженная модель.
- Зависимости Python зафиксированы в `uv.lock`, контейнерные образы — по digest. Точные digest весов: [runtime.json](../artifacts/runtime.json).

## Автоматические проверки

`pytest -q`: **19 тестов прошли**. Проверены авторизация, повторная загрузка, обновление и удаление, сохранение предыдущей версии при сбое, исключение неактивных векторов из поиска, TXT/Markdown/PDF, номер страницы PDF, ограничение chunked-тела запроса, JSON модели, придуманные ссылки, неподтверждённые числа, отказ на запросы актуальных цен, ретраи, метрики и отделение источников от системного промпта.

В интеграционных тестах Qdrant embedded работает реально, HTTP Ollama подменяется управляемыми ответами. Pytest выводит одно предупреждение Starlette о будущем переходе TestClient с httpx на httpx2; ошибок или пропущенных тестов нет.

Ruff: проверка кода и форматирования пройдена. Docker-образ API успешно собран, контейнер проходит healthcheck. Пересоздание API сохранило шесть документов в постоянном томе.

## Настоящая генерация

Сценарии `scripts/check_live.py` проверены последовательно, без параллельного бенчмарка поиска:

| Сценарий | Результат | Время HTTP |
|---|---|---|
| Нестандартные разъёмы и желаемая поставка на следующей неделе | Черновик с двумя источниками: комплектация и поставка | 30,67 с |
| Текущая цена и остаток Модуля А | Отказ сервиса до вызова модели: нужен API учётной системы | < 0,01 с |
| Автор романа «Евгений Онегин» | Отказ из-за отсутствия подходящих источников | 2,65 с |

Полные ответы: [live-generation.json](../artifacts/live-generation.json). Время одного запроса не является оценкой p95 или пропускной способности.

При разработке живая модель выявила две проблемы, которых не показала бы одна проверка HTTP: смешивание нового заказа с ремонтом и выдуманные цена/остаток с формально существующей ссылкой. После этого добавлены ограничение слабых фрагментов контекста, граница запросов текущих бизнес-данных и проверка неподтверждённых числовых токенов. Исходные проблемные ответы сохранены отдельно: [первый прогон](../artifacts/live-generation-initial.json), [проверка до ограничений](../artifacts/live-generation-before-guards.json).

Модель 1,5B иногда пересказывает регламент как инструкцию менеджеру вместо готового письма и может повторно спрашивать уже указанные сведения. Поэтому результат — редактируемая заготовка. Проверка ссылок и чисел не является полной проверкой фактов; автоматическая отправка клиенту не предусмотрена. Для следующего этапа нужны более сильная модель и оценка на реальных обращениях.

## Поиск

Результаты на **18 учебных вопросах с ожидаемыми источниками и 4 посторонних вопросах**. В корпусе шесть коротких вымышленных документов; набор открыт и использовался при разработке. Это smoke-бенчмарк, не закрытая оценка качества.

| Режим | Recall среди 5 фрагментов | MRR документов внутри 5 фрагментов | p50 HTTP | p95 HTTP |
|---|---:|---:|---:|---:|
| BM25 | 1,0000 | 0,9630 | 19,8 мс | 25,5 мс |
| Векторный | 0,7778 | 0,7778 | 252,6 мс | 299,4 мс |
| Гибридный RRF | 1,0000 | 0,9722 | 273,1 мс | 308,1 мс |

Все три режима вернули пустую выдачу для четырёх посторонних вопросов. Векторный поиск пропустил часть ожидаемых документов при пороге 0,45; это зафиксированный результат, а не основание считать выбранный порог оптимальным. Незначительная разница MRR на таком наборе не доказывает преимущества гибридного поиска на реальных данных.

Отчёт со всеми запросами и результатами: [retrieval-report.json](../artifacts/retrieval-report.json). Методика и ограничения: [evaluation.md](evaluation.md).
